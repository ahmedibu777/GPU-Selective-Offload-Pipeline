# Review 1 Experiment Protocol

## Status

FROZEN FOR REVIEW 1

## Scope

This protocol evaluates the CPU-first selective data offload prototype. It does not
evaluate CUDA kernels, TensorRT engines, Jetson deployment, or GPU inference.

GPU timing, including:

```text
T_H2D + T_kernel + T_D2H + T_sync
```

is explicitly deferred to the Major Project extension.

## Research question

Can Guarded Selective Priority offload retain a higher proportion of safety-critical and
high-value events than FIFO and matched-budget baselines while reducing transmitted bytes
and meeting delivery deadlines under controlled link stress?

## Dataset and event oracle

Use a curated autonomous-driving dataset with frame-level or event-level ground-truth
annotations. KITTI Raw Object Detection and nuScenes-mini are acceptable secondary
evaluation options.

The event oracle identifies event-positive ground-truth frames, such as anomalous,
safety-critical, or high-information frames. The selector does not need to train a
detector for Review 1; dataset annotations may serve as the event oracle.

## Six CPU baselines

| Baseline | Selection rule | Scheduling rule | Purpose |
|---|---|---|---|
| Upload-all | Select every generated frame | Arrival order | Upper-bound bandwidth reference |
| FIFO | Select frames until the byte budget is exhausted | First-in, first-out | Fair queueing baseline |
| Random | Select frames randomly until the byte budget is exhausted | Random order | Uninformed selection control |
| Value-only | Select highest `S_i` events until the byte budget is exhausted | Highest `S_i` first | Isolates value-score benefit |
| Deadline-only | Select events with positive remaining slack until the byte budget is exhausted | Highest `1 / D_i` first | Isolates urgency benefit |
| Combined | Apply safety guard, select highest-value eligible events, schedule by `P_i` | Highest `P_i = S_i / D_i` first | Proposed Review 1 policy |

All selective policies must use the same transmitted-byte budget as FIFO for a fair
matched-budget comparison.

## Frozen link-stress profile

| Profile name | Bandwidth | One-way latency | Packet loss | Emulation method |
|---|---:|---:|---:|---|
| constrained-urban-cellular | 8 Mbps | 60 ms | 0.5% | Linux `tc/netem`; `iperf3` calibration |

If `tc/netem` is unavailable because of container privileges, use the application-layer
token-bucket fallback. Record the emulation method in every result file.

## Metric definitions

### Event Recall

```text
Event Recall =
    Delivered Event-Positive Ground-Truth Frames
    / Total Event-Positive Ground-Truth Frames
```

Event Recall measures whether important annotated events were successfully delivered
before their deadlines. It is distinct from object-detection mAP.

### Bandwidth Reduction

```text
Bandwidth Reduction =
    1 - (Bytes Sent by Policy / Bytes Generated by Upload-all)
```

Report the result as a percentage.

### Latency

For each delivered event:

```text
End-to-End Latency = Delivery Completion Time - Event Creation Time
```

Report:

- P50 latency in milliseconds.
- P95 latency in milliseconds.

### Deadline Miss Rate

```text
Deadline Miss Rate =
    Events Completed After Deadline
    / Total Selected Events
```

Report the result as a percentage.

### Additional diagnostics

Record, but do not treat as primary Review 1 claims:

- Queue drop rate.
- CPU processing time.
- Bytes generated.
- Bytes sent.
- Number of 64 KiB chunks transmitted.
- Number of events rejected by the safety guard.

## Experimental procedure

1. Generate or load the frame/event sequence.
2. Apply the same event oracle and byte budget to every policy.
3. Run Upload-all, FIFO, Random, Value-only, Deadline-only, and Combined.
4. Apply the frozen `constrained-urban-cellular` link profile.
5. Record per-event delivery time, bytes sent, deadline status, and event-oracle label.
6. Aggregate results into one CSV file per policy.
7. Produce comparison plots for event recall, bandwidth reduction, P50/P95 latency, and
   deadline miss rate.
8. Repeat each configuration with at least three random seeds where randomization is used.

## Success criteria

The Combined policy should demonstrate:

- At least 30% bandwidth reduction relative to Upload-all.
- At least 95% event recall for safety-critical events.
- No more than 5% deadline misses.
- Lower or comparable P95 latency than FIFO under the same byte budget.

These are evaluation targets, not guaranteed results. Report measured values exactly.

## GPU boundary

No GPU timing is collected for Review 1. CUDA preprocessing, TensorRT inference, Jetson
deployment, and the GPU timing formula are Major Project extensions.
