# ADR-001: CPU-First Selective Offload Scope

## Status

LOCKED

## Decision

Review 1 shall implement a CPU-based, deadline-aware selective data offload prototype.
The prototype validates event-oracle selection, multi-factor value scoring, safety-guarded
priority scheduling, and quantitative evaluation against FIFO and matched-budget baselines
under controlled link stress.

## Locked implementation stack

- Core pipeline: C++17.
- Build system: CMake with Ninja.
- Platform: WSL2/Ubuntu.
- Testing: CTest.
- Sanitizers: AddressSanitizer and UndefinedBehaviorSanitizer.
- Analysis and plotting: Python, using pandas, NumPy, and Matplotlib.
- Link stress: Linux `tc/netem` and `iperf3`; application-layer token-bucket fallback is
  permitted in unprivileged containers.

## Explicit exclusions

The following are not Review 1 deliverables:

- CUDA kernels.
- TensorRT engines.
- Jetson binaries.
- Jetson hardware acquisition or outreach.
- GPU inference.
- GPU timing measurements.

## Major Project extension

After Review 1, CUDA preprocessing and TensorRT FP32/FP16 inference acceleration may be
implemented on the BMSCE RTX 4090 workstation. GPU timing shall be reported as:

```text
T_H2D + T_kernel + T_D2H + T_sync
```

## Locked prioritization formula

```text
S_i = w1 * R_i + w2 * U_i + w3 * C_i - w4 * A_i
P_i = S_i / D_i
```

## Canonical data model

`Frame` and `Event` shall retain:

- `Imu` and `Gps` metadata.
- `uint8_t priority`.
- Non-owning `const uint8_t* data_ptr`.

Dead stubs shall be removed. The repository must compile cleanly with CMake and Ninja and
pass CTest under ASan/UBSan.
